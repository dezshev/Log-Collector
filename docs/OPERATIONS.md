# Инструкция эксплуатации

Система: C# 5, .NET Framework 4.8, WPF. Для запуска нужен Windows с .NET Framework 4.8; для сборки дополнительно targeting pack 4.8 и компилятор C# (Visual Studio либо Build Tools). SDK современного .NET не является целевой платформой приложения. Сторонних пакетов нет.

## Сборка и проверки

Из корня проекта в PowerShell:

```powershell
.\build.ps1 -Test
```

Либо открыть LogCollector.sln в Visual Studio и собрать Release. После сборки csc программы находятся в build. Если корпоративная политика запрещает исполнение ps1, можно использовать Visual Studio / MSBuild; глобальную политику Windows менять не требуется.

## Запуск сервера

Задать собственный токен только для текущего процесса PowerShell, затем запустить:

```powershell
$env:LOGCOLLECTOR_ADMIN_TOKEN = Read-Host 'Токен администратора'
.\build\LogCollector.Server.exe 5050 .\data 127.0.0.1
```

Read-Host в этом примере вводит текст в консоль; не использовать токен в демонстрируемых снимках. Токен не входит в архив и исходники. Порт должен быть свободен, каталог доступен для записи. Сервер не удаляет архивные логи. При конфликте порта, недоступном каталоге или пустом токене запуск завершается с ошибкой.

Для штатной остановки нажать Ctrl+C в консоли сервера. После завершения закрываются сокеты и файл. Не запускать второй сервер в том же каталоге и не менять активный файл вручную.

## Агент и библиотека

В отдельном терминале:

```powershell
.\build\LogCollector.DemoAgent.exe WebServer 127.0.0.1 5050 100
```

Аргументы: источник, адрес, порт, число циклов по пяти уровням. Аналогично запустить Database и Worker. Клиент получает STORED либо FILTERED для каждой операции. Сетевую ошибку нельзя трактовать как FILTERED.

Стороннее приложение .NET Framework 4.8 добавляет ссылки на LogCollector.Common.dll и LogCollector.Client.dll. Пример API:

```csharp
using (RemoteLogger logger = new RemoteLogger("127.0.0.1", 5050, "MyApplication"))
{
    bool stored = logger.Log(LogLevel.INFO, "Приложение запущено");
}
```

При ошибке библиотека закрывает канал. Для нового соединения создать новый RemoteLogger. Автоматического повтора нет: если ответ потерян, предыдущая запись могла сохраниться. Чтобы избежать неосознанного дублирования, вызывающее приложение должно самостоятельно определить политику таких событий.

## Администратор

Запустить build/LogCollector.AdminWpf.exe, заполнить адрес, порт и тот же токен, нажать «Подключить». Если переменная среды задана в родительском терминале, токен подставится в маскированное поле. Выбрать источник в таблице либо ввести имя, выбрать порог и применить. Изменение не требует перезапуска или переподключения агента. При включённом автообновлении снимок запрашивается раз в секунду, без пересекающихся запросов.

Для консольного изменения:

```powershell
$env:LOGCOLLECTOR_ADMIN_TOKEN = Read-Host 'Токен администратора'
.\build\LogCollector.AdminConsole.exe 127.0.0.1 5050 WebServer ERROR
```

Правило для имени действует на все одноимённые соединения. Регистр значим. Настроенный, но отключённый источник остаётся видимым с нулём подключений. Лимит всех подключений 64, включая администратора; для новых правил предел 256.

## Журнал и отказы

Один активный logs-NNNNNN.log содержит записи всех источников. Штатный предел ротации 10 МиБ. Строки UTF-8 без BOM содержат UTC, уровень, источник и экранированный текст. Архивы удаляются только оператором после остановки и по его политике хранения.

При FAILED хранение находится в состоянии отказа. Читать статистику можно; новые подходящие записи не сохраняются. Остановить сервер, проверить свободное место, доступ и конфликт пути, устранить причину, запустить заново. При обнаружении неполной последней строки сервер удаляет только её незавершённый хвост и выводит число удалённых байтов. Целые записи остаются. Фильтры после перезапуска DEBUG, статистика нулевая: нужные пороги задать заново.

При потере сервера форма очищает текущие таблицы и сообщает ошибку. Отключение не является отменой уже применённого фильтра. Если результат изменения неизвестен, после повторного подключения проверить порог. Транспорт без TLS; используйте контролируемую учебную сеть.

## Обмен между компьютерами

На компьютере сервера определить адрес активного сетевого интерфейса и запустить сервер с этим конкретным адресом вместо 127.0.0.1. На компьютере клиента скопировать build с DLL и config, проверить наличие .NET Framework 4.8, запустить агента и GUI с адресом сервера. Настройка правил доступа к TCP-порту выполняется владельцем сети; проект сам не изменяет Windows Firewall.

Проверить регистрацию трёх источников, передачу пяти уровней, изменение ERROR для WebServer и независимость Database, затем отключить агент и проверить число подключений. Остановить сервер и подтвердить ошибку GUI. Записать ОС обеих машин, адреса, порт, времена, количество сообщений и наблюдаемый результат. Ручная проверка обмена между компьютерами отмечена как выполненная по подтверждению владельца проекта.

## Длительная проверка

```powershell
.\build\LogCollector.Tests.exe --load 180 .\docs\testing\load
```

Режим использует отдельный временный каталог, восемь клиентов и уменьшенную ротацию. Он создаёт CSV метрик и отчёт, проверяя соответствие подтверждений, счётчиков и файлов. Результаты повторного опыта могут отличаться; исходный отчёт комплекта фиксирует конкретный выполненный прогон.
