# TCP-протокол первого варианта

Версия спецификации: 0.1, 05.10.2026. Это собственный учебный протокол; не syslog и не HTTP. Одна TCP-сессия выполняет одну роль. В первом варианте версия не передаётся отдельным полем; несовместимые изменения требуют согласованного обновления клиента и сервера.

## Общий кадр

| Поле | Размер | Описание |
| --- | --- | --- |
| type | 1 байт | Беззнаковый код сообщения |
| length | 4 байта | Знаковый Int32, little-endian, длина тела без заголовка |
| body | length байт | Поля соответствующего типа |

Допустимая длина тела: 0-262144 байт. Неизвестный type, отрицательная / превышенная длина, неверное содержимое, незавершённый кадр приводят к отказу и закрытию только этого соединения. Нельзя считать один `Read` одним кадром; реализация читает требуемое число байтов в цикле. Отсутствие первого байта кадра означает штатный конец потока; отсутствие следующих байтов - обрыв кадра.

Строка во всех телах: Int32 длины в байтах, затем UTF-8 без BOM. Кодировка проверяется строго. Отрицательные длины и выход за предел тела запрещены. Лишние байты в конце тела запрещены. Используется явная длина, а не внутренний строковый формат `BinaryWriter.Write(string)`.

## Команды и ответы

| Код | Имя | Кто отправляет | Тело / результат |
| --- | --- | --- | --- |
| 1 | HelloAgent | Агент, первый кадр | Строка source; ответ READY |
| 2 | Log | Агент после приветствия | UTC ticks Int64, level byte, source string, message string; ответ STORED или FILTERED |
| 3 | HelloAdmin | Администратор, первый кадр | Строка token; ответ READY при совпадении |
| 4 | SetFilter | Администратор | source string, minimum byte; ответ UPDATED |
| 5 | GetStatus | Администратор | Пустое тело; ответ - строковый снимок состояния |
| 100 | Response | Сервер | Одна строка ответа |
| 101 | Error | Сервер | Одна строка ошибки; соединение закрывается |

На каждый запрос один ответ. В клиентской библиотеке обмен синхронный и сериализован блокировкой; нескольких запросов одновременно на одном соединении нет. Для параллельной отправки использовать отдельные экземпляры клиента.

В Log временная метка - число интервалов 100 нс с 01.01.0001 00:00:00 UTC, как `DateTime.Ticks`. Область допустимых значений соответствует `DateTime`, декодированная дата имеет `Kind=Utc`. В журнале дата представлена в ISO 8601 с суффиксом Z. По умолчанию агент ставит текущую UTC-метку; библиотека также принимает явный `LogRecord`.

Уровни: 0 DEBUG, 1 INFO, 2 WARN, 3 ERROR, 4 CRITICAL. Другие значения запрещены. Источник: 1-128 символов, не только пробелы, без управляющих символов; регистр значим. Поле source в Log должно совпадать с HelloAgent. Пустое сообщение допустимо, null нет; максимум 65536 байт UTF-8. Сообщение может содержать переносы строк, табуляцию и разделители.

Агент может отправлять только Log; администратор только SetFilter / GetStatus. Нельзя изменить роль в уже открытом соединении. После ошибки библиотека закрывает канал. При отказе администратору / агенту не возвращаются данные о чужих секретах.

## Снимок состояния

Response на GetStatus содержит TSV-строку с `\n` между строками:

```text
LEVEL   RECEIVED   STORED   FILTERED   FAILED
DEBUG   10         6        4          0
INFO    5          2        3          0
WARN    5          3        2          0
ERROR   5          4        1          0
CRITICAL 5         5        0          0
SOURCE  MINIMUM    ACTIVE_CONNECTIONS
Database DEBUG    1
WebServer CRITICAL 1
```

Здесь для читаемости показаны пробелы; на проводе разделитель `\t`. Ровно пять строк статистики в порядке уровней, затем заголовок источников и 0 или более строк источников. Источники отсортированы по имени. Настроенный, но отключённый источник остаётся со счётчиком 0; незаданный и отключённый источник исчезает. Два соединения с одним именем дают ACTIVE_CONNECTIONS=2.

Снимок формируется под общей блокировкой. Для каждого уровня выполняется RECEIVED = STORED + FILTERED + FAILED. В RECEIVED входят только корректно декодированные записи от зарегистрированного источника; некорректные пакеты в эти счётчики не входят. FAILED увеличивается при ошибке сохранения; STORED и положительный ответ в таком случае не выдаются.

## Фильтры, подтверждение и ограничения

- Порог по умолчанию DEBUG; правило для имени источника применяется ко всем его активным соединениям.
- Изменение SetFilter и обработка Log используют одну блокировку. После UPDATED все последующие обработанные сервером записи используют новое правило. Запись, уже обрабатывавшаяся раньше, могла быть сохранена со старым правилом.
- STORED отправляется после записи и Flush потока, FILTERED после обновления счётчика. Это не гарантия сохранности при отключении питания.
- Соединение и полный кадр ответа клиент ожидает до 5 секунд. Полное приветствие на сервере ограничено 5 секундами; после него разрешён простой агента до первого байта нового кадра. С первого байта весь оставшийся кадр имеет общий предел 5 секунд, а не новый срок на каждый маленький фрагмент. Запись ответа ограничена 5 секундами. Сетевой таймаут может завершиться с погрешностью планирования ОС.
- До 64 соединений суммарно, включая администратора и ожидающие приветствия. Избыточные соединения закрываются. До 256 настроенных источников; это удерживает размер снимка в пределах кадра.
- Токен администратора задаётся серверу и клиенту через `LOGCOLLECTOR_ADMIN_TOKEN`, длина на сервере до 1024 байт UTF-8. Транспорт без шифрования.
- После перезапуска фильтры сбрасываются на DEBUG, счётчики на 0; журнал не обнуляется.
- После ошибки записи журнал переводится в состояние отказа: последующие записи получают ошибку и увеличивают FAILED, администратор может читать статистику. Требуется устранить проблему хранения и перезапустить сервер. На старте незавершённый хвост последнего файла удаляется до последнего `\n`; число удалённых байтов выводится сервером.
- Автоматических повторов нет. Если ответ потерян, клиент сообщает ошибку; факт сохранения последней записи может быть неопределённым. Гарантия «ровно один раз» не заявляется.
- AdminClient.GetSnapshot преобразует TSV в проверенный неизменяемый ServerStatus; при некорректном снимке закрывает соединение. Формат на проводе не изменился; консольный GetStatus доступен.
- TcpChannel.Dispose прерывает выполняющийся Exchange закрытием сокета. Отключение не отменяет уже обработанную запись или применённый фильтр; поздние ответы в GUI отбрасываются по поколению соединения.
